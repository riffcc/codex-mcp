# Repository Guidelines

## Project Structure & Module Organization

- `src/` TypeScript sources (ESM):
  - `index.ts` MCP entrypoint (stdio server)
  - `tools/` MCP tools (`*.tool.ts`), `registry.ts`, `index.ts` (registration)
  - `utils/` execution, logging, parsing helpers
  - `constants.ts` shared types and strings
- `dist/` compiled output generated by `tsc`
- `docs/` VitePress documentation site
- `scripts/` maintenance utilities such as wiki deployment

Add tools under `src/tools/` and register them in `src/tools/index.ts`.

## Build, Test, and Development Commands

- `npm run build` compiles TypeScript to `dist/`
- `npm start` runs the compiled server
- `npm run dev` compiles once and runs locally
- `npm run lint` runs TypeScript type-checking with `tsc --noEmit`
- `npm run docs:dev`, `npm run docs:build`, and `npm run docs:preview` run the docs workflow

Requirements: Node `>=16` and a working `codex` CLI installation with authentication configured locally.

## Coding Style & Naming Conventions

- Use TypeScript ESM with `.js` extensions in source imports
- Use 2-space indentation and prefer single quotes
- Keep filenames in `kebab-case`
- Tool files should end with `.tool.ts`
- Keep `zod` schemas close to each tool and export a `UnifiedTool`

## Testing Guidelines

- There is no real automated test suite yet; `npm test` is currently a stub
- If you add tests, keep them near the source they cover
- Prioritize coverage for execution, parsing, and schema validation paths

## Commit & Pull Request Guidelines

- Use concise imperative commit messages
- Keep changes scoped
- Update docs when behavior or interfaces change
- Include reproduction steps or sample MCP interactions in PRs when useful

## Agent Notes

- Current exposed tools are registered in `src/tools/index.ts`
- For fast local iteration, `npx tsx src/index.ts` is useful
- Prefer tool arguments such as `approvalPolicy`, `sandboxMode`, `fullAuto`, `yolo`, and `cd` over hardcoded CLI flag logic

## Security & Configuration Tips

- Never commit secrets, local auth state, or machine-specific config
- Validate incoming arguments with `zod`
- Keep command execution limited to the intended Codex CLI flow
